Implementation guide

Architecture notes

A migration-friendly set of conventions for adopting a shared interface while preserving each toolchain's native responsibilities.

1. Markup contract

Use semantic HTML first. Reserve data-component for registry identity and data-* attributes for small, documented configuration values.

  • Use IDs for unique document targets.
  • Use classes for styling and reusable visual states.
  • Use ARIA attributes for accessibility, not runtime configuration.

2. Adapter lifecycle

Each adapter should expose a narrow lifecycle and avoid owning unrelated application state.

interface ComponentAdapter {
  mount(element: HTMLElement, config: ComponentConfig): void;
  destroy?(element: HTMLElement): void;
}

3. HTMX request flow

Keep request behavior declarative and return HTML fragments designed for the target region.

<button
  hx-get="/api/status"
  hx-target="#status-result"
  hx-swap="innerHTML"
>
  Refresh status
</button>

4. Design tokens

Define semantic CSS custom properties once, then map framework tokens to these stable names when needed.

:root {
  --color-accent: #496fe0;
  --surface-primary: #ffffff;
  --radius-control: 0.65rem;
}

5. Build pipeline

  • Validate HTML and HTMX integration metadata.
  • Run ESLint and TypeScript compiler checks.
  • Compile selected SCSS/SASS/LESS sources.
  • Run PHP lint and framework tests.
  • Apply migrations and execute database tests.
  • Run browser, accessibility, and end-to-end tests.

6. Incremental migration

Adopt the contract one component at a time. Wrap existing framework components with stable markup rather than rewriting their internals.

  • Document ownership of each component.
  • Define adapter-specific teardown behavior.
  • Keep backend routes versioned and explicit.
  • Remove duplicate implementations only after parity tests pass.
Suggested policy

Contract rules

RuleRecommendation
IdentifiersUse stable, lowercase kebab-case names.
ConfigurationPrefer documented data-* values; validate allowed values.
TransportUse HTMX for HTML-over-the-wire; define JSON APIs separately when required.
SecurityValidate input on the server, authorize every endpoint, and use parameterized SQL.
CompilationDo not attempt to compile server languages or preprocessors inside an HTML-only runtime.
